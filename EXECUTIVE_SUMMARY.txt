## 💡 Key Design Decisions

1. **Idempotency via Database:** ProcessedEvent table tracks already-processed events
   - Pro: Simple, auditable, survives restart
   - Con: Adds database write per event

2. **Vault via Config Server:** Secrets fetched at startup
   - Pro: Centralized, auditable, production-ready
   - Con: Requires Config Server + Vault (already in architecture)

3. **Per-Service Idempotency:** Each service has its own ProcessedEvent table
   - Pro: Isolated, no cross-service dependencies
   - Con: Data not shared between services

4. **EmbeddedKafka for Tests:** No external Kafka needed for unit tests
   - Pro: Fast, isolated, deterministic
   - Con: Can't test against real Kafka version
